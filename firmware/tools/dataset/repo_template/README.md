# DrillBalancer training data

Labelled recordings from the DrillBalancer (IMU + two microphones), made
with the app's **Training data** screen and uploaded by the app. They are
used to train the on-device drilling model (phases, material, mode/tool and
problems).

**This repository is private, and the data must stay private.** See
[Privacy](#privacy) before sharing anything from it.

## Layout

```
README.md                         this file
taxonomy/taxonomy.v1.json         label ids, phases and their windows
schema/meta.v1.schema.json        JSON Schema 2020-12 of meta.json
schema/events.v1.schema.json      JSON Schema 2020-12 of events.json
index.csv  stats.md               GENERATED by the Action, never edited by hand
.github/workflows/validate.yml    validates pushes, regenerates the index
recordings/YYYY/YYYY-MM/<id>/     one folder per recording
    meta.json      ids, device/app versions, IMU and audio settings, sync fit, session labels
    events.json    the labels: events, spans, holes (the only place labels live)
    imu.csv.gz     seq,t_us,ax,ay,az,gx,gy,gz,flags (raw int16 counts, board frame)
    level.csv.gz   the device's 10 Hz level readings, with the zero in effect on each row
    audio.flac     16 kHz, 16-bit, ch0 = MIC1, ch1 = MIC2
    audio_sync.csv frame,t_us per audio DMA block
    device_events.csv  optional: the device's own events (touches, vibration detector, profile)
```

`<id>` is `YYYYMMDDTHHMMSSZ_<install>_<rand>` (UTC start, a random per-install
id, a random suffix). All times inside a recording are device microseconds.

`taxonomy/` and `schema/` are copies of the contract in the main repo
(`firmware/tools/dataset/dbdata/contract/`). The Action checks that they
match; change the contract there, never here.

## How data gets here

- The app commits one recording per commit through the GitHub API. It only
  ever adds files under `recordings/`; a recording whose `meta.json` already
  exists is skipped.
- Editing labels in the app rewrites `events.json` (and `meta.json`) only;
  the data files never change.
- On every push to `recordings/**` the Action validates the new and changed
  recordings with `dbdata.validate` from the main repo (pinned tag
  `dataset-v1`), then regenerates `index.csv` and `stats.md` and commits
  them. An invalid recording stays in the repo with `valid=0` in the index;
  the loader skips it.
- Run it for every recording from the Actions tab (*validate*, *Run
  workflow*, *all*).

## Using the data

Clone this repo and the main repo, then use the `dbdata` package
(`firmware/tools/dataset` in the main repo; its README has the setup):

```python
from dbdata import Dataset

ds = Dataset(["~/data/Drill_Balancer_Data"], split="train",
             filters={"imu_profile": "RAW448", "mode": ["drill"], "material": "wood"})
a = ds.arrays()              # imu (K, N, 6), audio (K, 2, M), phase, weight, ...
```

The split is fixed per session (`crc32(session_id) % 10`: 0-7 train, 8 val,
9 test), so takes of one workpiece never end up in both train and test.

Checks by hand:

```sh
python -m dbdata.validate recordings/2026/2026-10/<id>
python -m dbdata.index . --check
```

## Limits

- One recording is at most 20 minutes (about 55 MB); every file stays below
  GitHub's 100 MB limit. No Git LFS.
- When this repo nears 5 GB, a new one is started for the next year; the
  loader accepts several roots.

## Privacy

- **Keep the repo private.** The audio can contain voices and room sound.
  Do not publish recordings, or anything derived from the audio, while it
  may contain voices.
- No personal data: the app records no location, time zone, names, emails,
  Android ID, phone serial or device MAC. The board id is a salted hash, and
  the reviewer is the random install id. The validator rejects files with
  such keys, and email or MAC addresses in text.
- Notes are free text of at most 200 characters: never write names or
  places into them.
- The app's upload settings can mute the audio while the motor is off
  (off by default); muted stretches are listed in `meta.audio.muted_spans_us`.
- Access is through a fine-grained token limited to this repo (contents
  read/write), stored encrypted on the phone.
